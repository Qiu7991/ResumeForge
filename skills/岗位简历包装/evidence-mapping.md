# 证据映射

## 核心问题

不是"这个项目跟岗位像不像"，而是"这个项目证明了什么能力，那个能力 JD 要不要"。

行业不同 ≠ 能力无关。行业相同 ≠ 能力对口。

## 证据强度四级

| 强度 | 判据 | 处理 |
|---|---|---|
| **强** | 有真实动作 + 可验证结果（上线、验收、压测数据、故障演练通过、真实用户） | 写进简历，排前面，重点展开 |
| **中** | 有明确动作，结果定性（搭建完成、跑通了、自己长期在用） | 写进简历，一条即可 |
| **弱** | 只学过、只看过、只了解原理 | 不进正文；技能栏可标「了解」 |
| **无** | 资料里没有 | **不写**，进待补清单 |

### 强证据的判断细节

"可验证"包括：
- 有数据：P95 19.6ms、787 处清零、200 台并发
- 有交付物：可烧录固件、部署上线的系统、打印出来的报告
- 有验收动作：真机验证、故障演练通过、客户验收
- 有真实使用：员工在用、学生在用、长期运行

**不成立**的"强"：
- 自己跑通一次 demo
- 跟着教程做出来
- 只写了代码没跑过
- 数字是从别处抄的/估的

### 中证据怎么写

中证据不要硬写成强证据。正确做法是**补细节**而不是**升措辞**：

```
弱写法：独立完成家庭网络搭建
中写法：以 Armbian + Docker 搭建家庭服务器，配 LXC-OpenWrt 旁路由分流、
       Samba 共享、RustDesk 远程协助，长期自用
```

补的是**做了什么**，不是**多厉害**。

## 反推映射（本方法的价值所在）

资料里的事实，往往没写明它证明了什么能力。要主动反推。

### 反推的三个方向

**方向 1：动作 → JD 语言**

| 资料原文 | 反推出的能力 | 简历写法 |
|---|---|---|
| 配 LXC-OpenWrt 旁路由、管 DNS | 局域网流量管理 | 「配置旁路由实现全网流量分流与 DNS 统一管理」 |
| 用 UFW / fail2ban 做防护 | 网络安全策略 | 「配置防火墙规则与暴力破解防护，完成访问控制」 |
| cron 每日 02:00 备份保留 7 份 | 数据备份策略 | 「建立每日自动备份机制，保留 7 个历史版本」 |
| systemd 托管 + 开机自启 | 服务可靠性 | 「用 systemd 托管服务并配置开机自启，保证异常后自动恢复」 |
| kill -9 后数据零丢失 | 数据可靠性验证 | 「以强制杀进程模拟断电，验证数据零丢失」 |
| 端口探测定位外网不通 | 分层排障方法 | 「通过本机/外网连通性对比定位入站拦截，确认是安全组策略问题」 |
| IE11 兼容 787 处清零 | 老旧环境适配 | 「面向 Win7 + IE11 的旧机房完成兼容改造，致命问题清零」 |

**方向 2：找出没明说但实际证明的能力**

| 做过的事 | 隐含证明了 |
|---|---|
| 做过断电/断网/崩溃/磁盘满/库损坏 5 类故障演练 | 有预案意识、懂故障分类、能系统性验证 |
| 把排查过程写成操作手册 | 知识沉淀习惯、可交接 |
| 给系统加操作审计（改前改后都记） | 合规意识、可追溯思维 |
| 压测出 P95 数据 | 有量化验证意识，不是"跑通就算完" |

这些**不要直接写成形容词**（"我有预案意识"），要融进 bullet 的事实里。

**方向 3：给每条能力找到"面试能讲"的落点**

写进简历的每个技术点，用户都要能讲 2-3 分钟。检查方法：问自己

```
如果面试官问「这个你怎么做的」，资料里有没有足够细节支撑一段完整回答？
```

支撑不了 → 降级或删掉。

## 相邻技术怎么写（「了解级」边界）

用户允许写相邻技术时，守三条：

1. **必须有真实依据的桥**。不是凭空加，是从已做的事自然延伸：
   ```
   ✅ 配过 nginx 反代 → 可写「了解反向代理与负载均衡原理」
   ❌ 只会装 Windows → 不能写「了解 AD 域管理」
   ```

2. **只能标「了解」，不能标「熟练」**。且要出现在技能栏或待补清单，
   不要写成做过的事。

3. **同时给出补法**。写到待补清单里，说明怎么补、补完能改成什么。

## 反面案例

### 案例 1：只挑看起来相关的（最严重的错）

```
JD：信息技术员（运维方向）
资料库：10 个项目
错误做法：按"技术相关"挑出 AI 简历工作台、CreatorDistill（都是软件开发项目）
结果：简历全是开发内容，跟运维岗完全不对口
```

```
正确做法：全量扫，找"运维动作"
发现：家庭网络自托管（旁路由/反代/防火墙/备份）→ 强
      英语测评系统（压测/故障演练/服务器部署/兼容改造）→ 强
      ESP32 康养系统（硬件调试/打板/装配）→ 中
结果：三个项目全部对上 JD 的"硬件维护 + 网络排障 + 系统配置"
```

### 案例 2：行业相同就以为是证据

```
JD：AI 应用运营
资料：会做 AIGC 视频
错误做法：把「会用 ComfyUI」当成 AI 能力证据
问题：会用工具 ≠ 懂 AI 应用落地
```

```
正确做法：找"运营动作"的证据
发现：做过公众号（选题、发布、复盘）→ 中
      CreatorDistill（分析爆款、拆解内容）→ 强（内容分析能力）
      有 AIGC 生产管线 → 强（内容生产效率）
```

### 案例 3：把中证据吹成强证据

```
资料：自己搭了个家庭服务器，长期在用
错误：独立设计并运维企业级高可用架构
正确：自建家庭服务器并长期维护，配置旁路由、共享存储与远程访问
```

后者没"企业级"三个字，但每条都能答得上，反而更可信。

## 映射表模板

做完整映射时用这张表，逐行填：

```
| JD 要求 | 对应证据（项目/经历） | 强度 | 动作 |
|---|---|---|---|
| 办公终端维护 | 英语测评系统 · IE11 兼容改造 | 强 | 保留，排第一 |
| 局域网组建 | 家庭自托管 · 旁路由 + DNS | 强 | 保留，展开 |
| 数据备份 | 英语测评 · cron 备份 7 份 | 强 | 保留 |
| 硬件维护 | ESP32 康养 · 打板 + 装配 | 中 | 保留，一条 |
| AD 域 | 无 | 无 | 待补清单 |
| IT 资产登记 | 无 | 无 | 待补清单 |
```

填完这张表，简历写什么就定了。
