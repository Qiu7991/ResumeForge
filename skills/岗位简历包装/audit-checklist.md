# 定稿审查清单

简历改完、写库之前，逐条过一遍。发现任一项不合格，先修再交。

## 一、真实性（最高优先级）

- [ ] **每条 bullet 能指回资料原文**。指不回去的删掉或降级。
- [ ] **没有把「参与」写成「主导」**。责任层级：支持/协助 < 参与 < 负责 < 独立负责 < 主导 < Owner
- [ ] **没有把团队成果写成个人成果**
- [ ] **没有把「了解」写成「熟练」**
- [ ] **每个数字都能解释**：怎么算的、基线是什么、跟我的动作什么关系
- [ ] **没有为了填满页面塞无关内容**

## 二、岗位匹配

- [ ] **JD 六层逐层核对过**，每层有证据或明确记为待补
- [ ] **项目排序按岗位相关性**，不是按时间或按"我觉得哪个厉害"
- [ ] **关键词出现在有证据的句子里**，不是只堆在技能栏
- [ ] **软能力用事实体现**，没写"服务意识强""认真负责"

## 三、表达质量

- [ ] **一条 bullet 一个主价值**，不是流水账
- [ ] **开头是强动作动词**（搭建/排查/定位/设计/配置/验证），不是"负责"
- [ ] **没有岗位说明书句式**（"负责 XX 维护工作"这种，换个人也能写）
- [ ] **技术点写到能证明能力为止**，不是堆名词
- [ ] **没有 AI 腔/黑话**（赋能、抓手、闭环、打造、助力）

## 四、可追问性（面试存活率）

对每一条重点 bullet，问：

- [ ] **能讲 2-3 分钟吗？** 讲不了说明细节不够或不是你做的
- [ ] **面试官追问一层还答得上吗？** 比如写"配置防火墙"，要能说清配了哪些规则、为什么
- [ ] **如果问"为什么这么做"有答案吗？** 有取舍思考才经得起问

## 五、篇幅与版面

- [ ] **一页装得下**（应届/初级岗）
- [ ] **内容不足时补细节，不补无关项目**
- [ ] **没有半页空白**：空就用具体细节填（怎么发现的、怎么定位的、踩了什么坑）
- [ ] **没有内容被裁切**：技能行等长行要检查右侧是否被截断

## 十二种高频失败

定稿前对照检查，发现即修：

| # | 失败模式 | 表现 | 修法 |
|---|---|---|---|
| 1 | 流水账 | 只有"负责/参与/协助" | 补动作、方法、结果 |
| 2 | 岗位说明书 | 删掉公司名能放进任何 JD | 加入具体场景和判断 |
| 3 | 空洞自评 | "认真负责、学习能力强" | 删掉或换成事实 |
| 4 | 教育堆料 | 课程/GPA 挤掉核心经历 | 压缩教育栏 |
| 5 | 数字装饰 | 数字与个人动作无关 | 删数字或写清关系 |
| 6 | AI 腔 | 说不清具体做了什么 | 换成大白话 |
| 7 | 项目目的不成立 | 解释不了为什么做 | 补一句背景 |
| 8 | 关键词堆叠 | 技术名词多但无证据 | 删到有证据的为止 |
| 9 | 过度包装 | 实习生像 COO | 降级措辞 |
| 10 | 通用简历 | 一版投所有岗 | 按 JD 重排 |
| 11 | 无关填充 | 无关证书/兼职占版面 | 删 |
| 12 | 前后不一致 | 简历与资料对不上 | 以资料为准 |

## 待补清单的写法

用户选了「允许写了解级相邻技术」时，**必须**单独给这份清单，不能让用户误以为已具备。

```
【待补 1】AD 域与组策略
- JD 要求：熟悉 Windows 及主流操作系统的使用与维护（第 2 层硬技能）
- 现状：资料里没有任何域环境相关经历
- 补法：装 Windows Server 虚拟机 → 建域 → 加一台客户端 → 推一条组策略（约半天）
- 补完可写：「搭建过 Windows Server 实验域，完成账号管理与组策略下发」
- 风险：面试若问「域控和工组有什么区别」必须答得上

【待补 2】IT 资产台账
- JD 要求：参与 IT 资产登记、盘点及管理（第 1 层核心任务）
- 现状：无
- 补法：用 Excel 建一张设备台账（编号/型号/使用人/位置/状态），约 1 小时
- 补完可写：「用台账表管理设备信息，按季度盘点核对」
- 风险：低，这类工作本身不复杂
```

**清单里每一条都要有：JD 依据、现状、补法、补完怎么写、面试风险。**

## 交付格式

最终给用户三样东西：

1. **改写方案**：逐条 before/after + 依据
2. **待补清单**：缺什么、怎么补
3. **已落库**：改了哪些字段（用 update_resume_field 之后的确认）

不要只丢一份新简历——用户看不出改了什么、为什么改。
