# JD 六层拆解

## 为什么要拆六层

关键词匹配只看"字面有没有这个词"。人看 JD 看的是"这个人要干什么、在什么环境里干、
需要什么能力"。拆成六层，才能把"用词不同的同一件事"对上。

## 六层定义

### 1. 核心任务

JD 里"负责 / 参与 / 协助"开头的句子，去掉修饰词，留下动词 + 对象。

```
原句：负责公司计算机硬件、网络设备及办公终端的日常维护与故障排除
核心任务：终端维护、网络设备维护、故障排除
```

**用途**：决定简历里哪些项目排前面。任务重合度最高的项目排第一。

### 2. 硬技能

必须会用的工具、系统、协议。通常出现在"熟悉 / 掌握 / 了解 + 名词"里。

```
原句：熟悉 Windows 及主流操作系统的使用与维护
硬技能：Windows、Linux/Mac（"主流操作系统"的展开）
```

**注意**：中文 JD 常写抽象词（"主流操作系统"），要展开成具体的（Windows / Linux）。
但展开后的每一项，资料里都要有证据，否则进待补清单。

### 3. 业务能力

处理什么类型的问题、面向谁。

```
原句：响应内部员工的技术支持需求，提供及时有效的 IT 服务指导
业务能力：内部用户支持、问题响应时效、服务意识
```

**用途**：决定 bullet 的叙事角度。同样做了一套系统，「给内部员工用」和「自己玩」
写法完全不同。

### 4. 场景经验

什么环境、什么规模、什么约束。

```
原句：协助进行公司信息系统的基础配置、数据备份及安全监控
场景：企业内网、有数据可靠性要求、有安全合规要求
```

**线索词**：公司、内部、机房、办公、生产、线上。这些词暗示了环境复杂度，
有对应经验的项目要优先。

### 5. 软能力

```
原句：具有良好的服务意识和问题解决能力，工作细致且具备较强的责任心
软能力：服务意识、问题解决、细致
```

**关键**：软能力**不要直接写**"我有服务意识"。要用事实体现——
"把排查过程整理成操作手册，便于同事按记录复现"就是细致 + 知识沉淀。

### 6. ATS 关键词

会被机器扫的词。通常是技能名词 + 岗位名 + 行业术语。

```
ATS 关键词：操作系统、故障排除、IT 资产、技术支持、局域网
```

**用法**：这些词要**自然地出现在有证据的句子里**，而不是堆在技能栏。
「排查局域网故障」比技能栏写「局域网：熟练」有用得多。

## 按岗位类型的拆解重点

### 技术 / 运维 / 支持岗

重心在第 1、2、4 层。第 5 层软能力只需一条事实体现。

```
必答问题：
- 每天要处理什么故障？
- 用什么工具定位？
- 环境的约束是什么（老旧设备、不能停服、多人共用）？
```

### 产品 / 运营岗

重心在第 3、5 层。硬技能反而不是重点。

```
必答问题：
- 面向什么用户？
- 做什么判断？
- 结果怎么衡量？
```

### 应届 / 无对口实习

重心在第 2、6 层，靠项目和课程补第 1、4 层。

```
策略：把课程项目/个人项目按"缩小版真实场景"写
但要诚实：不能包装成商业系统
```

## 一个完整的拆解示例

JD：广州好粟 · 信息技术员（7-8K · 校招）

```
1. 核心任务
   - 计算机硬件、网络设备、办公终端维护
   - 故障排除
   - 信息系统基础配置
   - 数据备份、安全监控
   - 技术支持响应
   - IT 资产登记、盘点、管理

2. 硬技能
   - 计算机软硬件基础
   - Windows 及主流操作系统
   - 局域网组建原理
   - 网络连接与设备故障排查

3. 业务能力
   - 内部员工支持
   - 及时响应
   - IT 服务指导

4. 场景经验
   - 企业内网
   - 办公环境
   - 有数据可靠性要求

5. 软能力
   - 服务意识
   - 问题解决
   - 细致、责任心
   - 沟通协调

6. ATS 关键词
   操作系统、沟通协调、故障排除、局域网、IT 资产、技术支持
```

**拆完之后的第一判断**：这个岗 90% 是"修电脑 + 管网络 + 装系统 + 记台账"，
不是开发岗。所以简历里所有"做系统开发"的项目都要**换成运维视角讲**，
讲开发框架没有意义。

## 常见误判

| 误判 | 后果 | 正确做法 |
|---|---|---|
| 把 ATS 关键词当硬技能 | 堆一堆没证据的词 | 关键词只用来核对覆盖，不作为写什么的依据 |
| 忽略第 4 层场景 | 项目讲得再好也不像"能干活的人" | 找有真实环境约束的项目优先 |
| 软能力直接写形容词 | 空话，HR 直接跳过 | 用一条具体事实体现 |
| 只看标题判断岗位 | 「信息技术员」可能是开发也可能是运维 | 一定读 JD 正文 |
